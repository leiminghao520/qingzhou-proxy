日期：2026-10-29。分支：`codex/android-windows-preview`；开始实施时 HEAD：`f1da505fdd3166ccbe7701174f518aa863861a05`。当前工作区含此前未提交的连接恢复、授权服务和界面修改，本次在其基础上继续实现，未重置或覆盖原有工作。

## 实现结果

- 统一线路切换事务：主列表、菜单栏、手动策略组使用同一核验、提交与回滚流程；读取核心的实际选择，检测目标节点。三项探测全失败不能确认成功；网站局部异常不掩盖目标节点通过；节点超时保持未确认，后台复查。组内重试不会改写默认选择。
- 自动选择继续使用核心 URLTest，用户选择始终为 `auto`，实际出口单独刷新。手动线路不隐式加入自动组。网络事件和明确节点失败触发复查，30 秒限频，保留核心容差及已有连接。
- 默认出口与各规则出口独立累计明确失败；其他规则节点健康不清零默认出口故障计数，局部规则出口异常不触发整套网络重建。
- helper 已授权会话恢复等待改为 1/2/4/8/15/30 秒后每 30 秒复查，无总次数上限。首次准备仍使用原有限预算，所有权冲突及恢复失败立即停止，停止命令使旧回调失效。
- App 基础网络缺失时释放自有接管、保留本次连接意图，网络变化唤醒同一协调器；没有物理网络不消耗重建次数。持续明确节点/控制故障最多三次重建后终止并核验释放。用户停止、退出撤销自动恢复，重启遵循已有自动连接设置。
- 恢复结束仅在释放核验通过后显示原网络设置已恢复；外部代理、企业 VPN 与指定出口拒绝保护继续遵循原有所有权边界。
- 主窗口和菜单栏区分接管与可用性；备用方案直接解释接管或 DNS 变化；简洁订阅页补齐剩余流量、到期、上次成功和下一次重试，缺失数据明确为未知。
- 订阅和规则暂态失败从快速重试转每小时复查；网络恢复后只重新调度暂态错误，鉴权/格式/失效地址仍等待人工处理。首次使用提供导入、策略、接管范围与授权说明，核验可用后可完成引导。

- 仓库要求的全项目 100% 行/分支及至少 80% 全项目变异分数**未达成**。本次覆盖报告全项目行覆盖 61.33%；Swift 工具没有输出分支数据；定向变异不可冒充全项目指标。应用事务及管理员服务不在纯策略覆盖统计中。

- 真实 Wi‑Fi 断开与恢复、热点切换、物理睡眠唤醒、管理员 helper 更新、系统代理动态发布、VPN 共存及异常退出后的实网清理均**未验证**。本次没有中断用户当前网络、安装候选版本、替换 helper、提交或推送。
- 自动组能恢复新请求，不承诺既有 TCP 会话透明迁移；界面明确提醒失败请求可能需要重试。
- 未引入自动升级系统或更改对外订阅格式；新增状态保留旧配置可读取，恢复意图不跨应用重启持久化。
