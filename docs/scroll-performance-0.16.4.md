# 0.16.4 概览滚动性能优化

## 原因与修改

原速率图按 30 分钟逐秒历史生成四类 Swift Charts 标记，1800 个样本需要约 7200 个绘图标记。实时指标更新与整个概览布局叠加时，会增加主线程负担。实机只读采样也观察到 Charts 调用栈参与工作，但未将采样比例解释成精确的滚动帧率。

速率图现在将绘图投影限制到最多 254 个点：每段分别保留上下行的最大和最小值，并保留首尾及时间顺序。折线细节会被压缩，逐秒速率、完整历史、总流量和悬浮取值仍读取原始数据，连接业务逻辑不变。264 项投影断言验证逐段峰谷、端点、顺序、点数上限与输入等价比较。

图表输入相同时通过 Equatable 跳过无关父页面刷新；完整输入比较包含标识、时间、上下行值，避免仅比较末尾导致内容修改不显示。概览改为延迟构建离屏卡片，保留原滚动和交互能力。

## 量化检查

固定 1800 个样本，680 × 210 的隔离图表，先预热一次，再记录 7 次逐秒追加后的视图更新、布局和位图绘制耗时。

| 指标 | 0.16.3 原组件 | 0.16.4 新组件 |
|---|---:|---:|
| 中位耗时 | 81.12 ms | 17.24 ms |
| 最长耗时 | 82.78 ms | 17.53 ms |

本轮中位耗时减少约 78.7%。首次试跑约 183 → 21 ms；复测受缓存和系统调度影响，采用上表同轮结果作为交付依据。此基准测量图表更新成本，不代表实机滚动 FPS，不声称已验证固定帧率。

图例检查补充 1800 点长会话、宽窄嵌入与独立卡片，覆盖深浅色；原始渲染、日志与性能 JSON 随交付记录保存。未清空或缩短真实流量历史来获得上述结果。

## 验证与交付

最终检查、安装、连接状态及用户体感反馈以输出目录中的 `0.16.4-滚动优化记录.md` 和 `安装记录-0.16.4.json` 为准。性能脚本可执行 `bash scripts/chart-legend-checks.sh /绝对路径/结果目录 '' --performance`；与旧组件比较时第二参数传入旧 `RateChart` 结构的源码文件。
