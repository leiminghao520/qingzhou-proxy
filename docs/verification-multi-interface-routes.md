# 多网卡同前缀路由修复验收

## 修复行为

本机截图对应 `169.254/16` 的全局 `en0` 路由和接口限定 `en6` 路由。旧逻辑将两条路径直接用于按目标地址拆分的核心规则，因同前缀不同接口拒绝启动。

`CapturePlan.effectiveRoutes(_:resolvers:)` 按同前缀选择有效出口，原始快照保持完整。唯一全局出口优先，其他接口限定路径不转为全局保护项。只有接口限定路径时，仅接受带明确保护域名的 DNS 接口所指向的唯一出口；无法唯一选择时不发布该网段的核心规则，相关企业解析地址经保护核验失败后不返回，不回退公共 DNS。多个不同全局出口仍拒绝，错误包含接口、网关和作用域。

启动静态配置、动态规则、写入保护和网络重规划均使用计划中选择后的 `protectedRoutes`。企业 DNS 地址必须与核心已确认的最长匹配出口一致，防止按 DNS 接口查询却从另一接口访问。回环路径保留原处理。旧计划的物理保护项可按完整所有权安全撤回；外部改写不能当作正常撤回放行，恢复操作不删除外部路径。

本轮沿用上一轮尚未提交的组播修复及其回归；版本设为 `0.10.2 build 44`。无配置持久化格式变更。
