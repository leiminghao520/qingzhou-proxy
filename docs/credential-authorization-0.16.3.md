# 0.16.3 凭据授权优化

## 问题与原因

旧实现为每个节点、订阅和历史加密密钥分别创建通用密码条目。macOS 钥匙串的访问许可按条目管理，复用 LAContext 不等于合并各条目的许可。本机没有可用的正式代码签名身份，当前本地包使用临时签名；应用更新改变签名后可能再次要求授权。Helper 保持原有客户端身份核验，不通过放宽验证来减少管理员提示。

## 行为变化

- 将新的和已成功读取的旧凭据收敛到一个钥匙串条目，保留原服务名、业务引用和配置格式。
- 前台成功读取后在本次进程复用；启动历史初始化、启动自动连接、后台维护和唤醒恢复禁止弹出钥匙串窗口。
- 启动自动连接发现辅助服务未获授权时停止并提示手动处理，不自动弹管理员窗口。
- 同一次手动连接中取消或拒绝钥匙串许可后，停止后续系统凭据查询与写入。再次手动连接可以重试。
- 拒绝授权、存储损坏不当作“凭据不存在”，不生成新历史密钥覆盖原密钥。
- 迁移写入失败仍可使用本次已获准读取的旧值，旧条目不删除；明确写入或删除失败保持原缓存。删除标记防止旧引用被重新读回。
- VPS 联动与维护命令使用相同集中存储；旧业务引用仍可按需兼容读取。

## 边界

合并完成且钥匙串已允许访问时，日常连接复用凭据。首次迁移旧条目仍可能逐项确认；本版本不声称首次迁移只输入一次密码。尚未使用的旧凭据会在首次使用时迁移。迁移写入失败会在下次读取重试。

辅助服务的管理员许可与钥匙串许可是两套系统授权，不能承诺合并为一个系统窗口。本地临时签名更新后仍可能要求重新许可。密码完全由 macOS 窗口处理，应用不保存 Mac 登录密码，也不改变钥匙串访问控制、辅助服务客户端验证或文件权限。

## 验证口径

维护修复按行为测试与现有项目检查验收。授权模拟测试验证存储、取消、失败原子性与静默策略；不能替代真实系统密码窗口的数量验收。安装后的启动、线路连接与授权次数另记，未观察到的行为不得标为通过。
