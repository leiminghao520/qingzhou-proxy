# 诊断、单份配置历史与网络事件候选验收

日期：2026-10-23。源码基线：`7507707`，分支 `codex/android-windows-preview`。保留此前尚未提交的稳定性与性能优化，以及原有 `OPTIMIZATION_GUIDE.md`、`examples/`。

## 交付范围

- 诊断页共用三个页签：综合诊断、目标路径、事件时间线。配置卡片提供单配置历史，另有全部历史入口，可找回已删除配置。
- `DiagnosticSession` 固定诊断 ID、配置 ID、连接代次和节点 ID。配置切换、断开、重连及再次诊断使旧结果失效；停止诊断保留已完成阶段，并明确标记未完成阶段。连接时使用实际出站信息，断开时使用明确选中的节点，无法确定时不取列表首项。
- `DiagnosticExecutor` 总等待预算 30 秒。DNS 与目标路径同步系统查询进入两个共享后台槽位，单项等待 3 秒；超时或取消后，仍未返回的系统调用继续占槽。后续调用返回“未验证”，不会增加线程。
- 辅助服务诊断使用独立只读客户端，取消不会关闭当前代理持有的控制通道。端口可绑定、占用者未确认与代理 HTTPS 入口验证分别呈现。
- 结果包含结构化状态、原因码、检查时间与耗时。文本和 JSON 导出只包含白名单元数据及安全说明，不包含目标、原始错误、节点地址、订阅 URL 和凭据。
- 目标路径复用规则模拟、系统代理选择及原生只读路由查询；展示配置预期和当前系统结果，不把路由查询或系统代理选择当作业务连接通过。

## 历史格式与事务

路径为用户数据目录下 `ProfileHistory/`；隔离检查使用临时目录与内存凭据，不访问日常钥匙串。

| 文件/项目 | 内容 |
|---|---|
| `options.json` | 自动历史开关，默认开启 |
| `index.qzh` | 加密版本索引，包含时间、来源、逻辑摘要、保存及连接验证状态 |
| `<UUID>.qzh` | 单份配置和恢复必需的凭据内容 |
| `pending.qzh` | 候选历史事务 ID 与待提交版本 |
| Keychain 引用 | `qingzhou.profile-history.key.v1`，256 位随机对称密钥 |

`.qzh` 是独立的版本 1 JSON 信封，载荷为 AES-GCM 的随机 nonce、密文和认证标签；认证附加数据绑定格式版本和文件名。索引、候选事务和快照均加密。目录权限 0700，文件 0600，持久写入使用原子替换与同步。原有口令备份格式不变。

逻辑摘要排除测速、最近使用、流量、自动更新重试及错误等观测字段，并以凭据内容摘要替代临时引用。仅重建引用或更新运行状态不新增历史。默认每配置最多 20 个版本、30 天，总计 100 MiB；启动、配置事务及运行时按小时维护保留期，忙碌时推迟维护；新事务在停连接之前预留变更前快照与候选的容量，空间不够则中止变更。

事务顺序：

1. 建立候选凭据，校验配置。
2. 对账已有历史事务；保存并回读核验变更前快照和候选，落盘候选事务；失败清理本次临时凭据，保留原配置和连接。
3. 需要重连时沿用“停止、启动候选、验证”的运行事务；失败恢复原运行配置。
4. 主配置原子提交，同时写入可选 `lastHistoryTransactionID`，旧配置集合缺少此字段仍可读取。
5. 完成历史索引，最后清理不再被当前配置集合引用的旧凭据。

若主配置提交成功但历史收尾失败，界面显示“历史收尾待对账”，不谎报主配置已回滚。下次变更/启动按主配置的事务标识完成或撤销未决候选；索引已完成但事务文件未删除时，不重复提交，不删除已提交快照。崩溃对账不会宣称真实连接验证通过。

恢复仅替换选中配置，保留其他配置和当前选择；已删除配置以新 ID 恢复。预览后配置再发生变化时要求重新预览，未保存草稿沿用离开确认。恢复当前运行配置明确确认重连；恢复非当前配置只保存。恢复的订阅、远程规则暂停自动更新，并清除待重试状态，预览明确说明。

## 故障恢复说明

- 历史初始化失败：显示“历史未就绪”，原代理会话继续运行。关键配置变更在准备阶段阻止；断开、恢复网络、退出不依赖历史成功。
- 密钥缺失或快照损坏：拒绝解密及覆盖已有历史，不生成替代密钥覆盖旧数据。若原密钥无法恢复，旧加密历史不可解密；可关闭历史继续修复当前配置。清空历史后再开启会建立新的基线。
- 主配置已提交、历史收尾失败：保留 `pending.qzh` 和主配置事务标识，修复目录/磁盘后重新启动或执行下一次配置变更完成对账。
- 清空历史只清理历史索引、候选和历史快照，不删除当前配置、节点凭据、历史密钥或手工备份。
- 临时凭据写入失败：撤销本次创建的引用；不会删除其他配置仍引用的凭据。

## 网络事件

使用独立 `network-events.jsonl`，与普通诊断日志、路由审计分开。只记录有限类别、结果、原因码、阶段和不透明关联 ID，不接收任意 URL、凭据、普通日志正文或逐条业务连接。

同会话连续相同原因在 30 秒窗口合并，累计次数；不同配置、会话、阶段、诊断 ID 和历史事务不合并。默认保留 7 天、文件不超过 2 MiB，界面最多最近 1,000 条。待写入最多 1,000 条，单个在途写入批次最多 1,000 条；高频超限丢弃最旧待写事件并显示计数。写入失败仅提示一次，不触发断开或恢复网络。独立发布模型防止事件变化刷新整个应用；取得单实例锁后才加载/清理事件文件。
