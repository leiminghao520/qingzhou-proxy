# 0.8.18 恢复与退出冲突修复

日期：2026-10-18；版本：0.8.18（32）。

## 现场及原因

0.8.16 在 12:20 检测到 `128.0.0.0/1` 原记录的出口已被 `utun7/link#26` 替换，停止核心并保留恢复记录。恢复按钮和退出入口重复调用严格恢复，因同一冲突一直失败；退出还将“恢复记录为空”作为必要条件，导致核心已停止仍不能退出。

本轮首先执行已安装辅助服务的 `--recover-preserving-external`，仅清理仍属于轻舟的路径，归档旧记录到 `recovery-preserved-6797BC7D-AA8A-43D7-8578-0DC794C62E69.json`。随后通过标准退出事件正常关闭旧应用，未强制结束进程。核验默认出口始终为原 `utun7`，没有关闭或修改 Shadowrocket。

## 修复

- 用户恢复和退出显式请求 `preserveExternal`；自动停止、启动失败回滚仍保持严格策略。辅助服务协议保持 4，新增可选能力、待恢复及安全退出字段；旧辅助服务不具备能力时明确提示更新，不能悄悄忽略标记。
- 对系统代理逐协议核对：清理仍指向轻舟的回环入口，保留后来修改的外部协议及相关配置；部分恢复或归档失败时保留原记录，不宣称恢复成功。回环别名 localhost/::1 不能绕过入口核验。
- 路由恢复保留外部替换项，仍属于轻舟的路由按原网关、接口、作用域核对后清理；竞争出口、写入失败或读取失败不当成已恢复。完整归档后才移除活动恢复记录。
- 退出使用独立的释放核验：核心、待重连会话、路由、DNS、代理均不再指向轻舟时，允许保留恢复记录退出。仍有接管或无法证明已释放时仍拒绝退出，保留具体错误。辅助服务运行缓存以新状态更新，不能把已停止核心误认为仍运行。
- 正常恢复成功清除旧弹窗错误，退出请求合并为单个任务。
