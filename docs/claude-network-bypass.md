# Claude 保护与网络绕过兼容（0.16.16 / 99 候选）

本文件记录 0.16.16 历史行为；0.16.17 云枢控制面重连修复以 [云枢控制面说明](yunshu-control-reconnect.md) 为准。

## 行为与启用

首页新增“Claude 保护下允许网络绕过”，默认关闭。旧配置及活动会话不自动启用；更换范围须先使用现有“解除保护并恢复直连”入口，再选择兼容选项并重新开启 Claude 安全模式。解除期间 Claude 可以直连，应先结束 Claude 使用。

开启兼容后，复用全部已启用绕过项，不限于同盾域名。普通公网仍通过固定节点，保留严格代理 DNS 和断线屏障。企业域名使用原作用域 DNS，未声明绕过的域名继续代理解析。企业解析失败不会回退公共 DNS。没有企业解析器时，显式绕过域名可以使用已核验的原默认解析器。

这不是应用级隔离。Claude 和其他程序均可访问例外目标；共享 IP 上的其他服务也可能被放行。IP/CIDR 例外允许其原出口上的业务协议；DNS 专用例外仅开放指定服务器的 TCP/UDP 53。不要将本机或局域网代理服务加入绕过后，仍宣称 Claude 无法借它联网。

## 路由与防火墙

- 核心配置、作用域 DNS 和 PF 同时支持例外；不会只修改分流规则而保留阻断内网的旧 PF 配置。
- 每条例外同时约束目标与原出口接口。用户网段跨多个原出口时按最长前缀切分；无法确认、范围过大、竞争出口或超预算时拒绝配置。
- 不按自动发现的整个 VPN 网段扩大例外。域名成功回答前，先核验原路由，再加载并核验 PF 目标例外。新回答替换该域名的旧目标；撤销时清理相应已有连接状态。
- 原有企业防火墙拒绝继续生效；生成拒绝规则，不添加绕过其他防火墙的放行规则。
- 网络变化先撤销旧例外，再串行重建；快照不可核验时收紧并重建。暂停、停止或 helper 重启后撤销例外，重新连接核验后恢复。此阶段企业业务可能中断，公网屏障保留。
- 系统重启、接口被特权程序复用、企业软件改写 PF 的空窗仍须实机验证，不能以轮询或离线夹具证明持续保护。

## 企业客户端依赖

堡垒机业务依赖企业客户端登录、心跳及隧道连接。已知云枢控制域名为 `sp.eagleyun.cn`、`idp.eagleyun.cn`；界面会对已安装云枢且未覆盖这些目标的配置提示缺项，不自动增加 IP 或放行整个 VPN。

这些域名并非所有企业网络的完整依赖清单。应在验收时核对实际使用的客户端及连接。指定网卡绕过沿用原拒绝保护要求，系统 PF 结构不兼容时拒绝启动。

## 验证与回退

运行 `bash scripts/claude-bypass-checks.sh`。检查仅使用隔离配置、模拟管理员命令和本地组件；`sing-box check` 与 `pfctl -nf` 只检查配置，不启动真实 TUN 或加载系统 PF。

实机验收须覆盖：堡垒机页面、登录和会话；全部现有绕过目标；企业客户端登录及心跳；IPv4/IPv6、DNS、UDP、已有连接；节点不可达、核心/GUI/helper 退出、VPN 断开、休眠和网络切换。未完成前仅交付候选包，不称为线上修复完成。

安装候选需要更新 helper 并批准新组件哈希；旧 helper 在改变连接前被能力检查拒绝。回退前使用明确解除入口恢复原配置，再安装旧包，不能让旧 helper 读取未知兼容记录。应急恢复命令沿用 `docs/claude-pf-v2.md`，它会解除保护并允许直连，不应作为一般重连操作。
