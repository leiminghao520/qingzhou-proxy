# 云枢控制面与 Claude 保护共存修复（0.16.19 / 102 候选）

## 问题与行为

0.16.16 只复用业务绕过项，未在阻断前准备云枢控制连接。首次启用清理已有 PF 状态后，云枢登录、心跳和隧道无法可靠重连；暂停时又撤销了全部例外。缺项提示不能替代控制链路兼容。

新候选在“Claude 保护下允许网络绕过”已开启、且本机安装云枢时，额外准备云枢控制面：

- 使用原物理网卡 DNS 提前解析 `sp.eagleyun.cn`、`idp.eagleyun.cn`，并尝试 `mqtt.cs.eagleyun.cn`。必要解析失败时停止准备，不宣称已连接。
- 只采纳固定安装位置、通过云枢厂商 Apple 签名要求核验的正在运行进程。联网采样前后再次核验身份，采纳其已连接或尝试连接的精确公网 IP、端口和 TCP/UDP；拒绝私网及代理合成地址，限制数量。
- `eagleyun.cn`、`eagleyun.com` 的运行时域名例外使用原物理 DNS 和原出口，不经云枢自身。它们不写回用户保存的绕过清单。厂商域名动态答案默认只开放 TCP/UDP 443，MQTT 额外开放 TCP 8883；已核验进程端点可补充实际使用端口。
- PF 和核心规则同时限定地址、协议、端口及原接口。同地址多个合法端口取并集，不生成错误的多个否定条件。控制地址的主机路由在系统捕获路由启用前准备。
- 堡垒机等企业业务继续使用企业解析器和 VPN；已标记为企业保护的历史域名在 VPN 解析器消失时拒绝回退到公网 DNS。

首次开启仍会清理原有 PF 连接状态，可能触发云枢短暂重连。本修复保证的是准备其重连路径，不承诺无感切换或所有版本的云枢都零中断。

## 暂停、重连和恢复

暂停、退出或代理重建时，仅撤销普通业务例外，保留云枢控制端点和必要的原网卡 DNS。公网固定节点限制继续生效。

控制面维护独立于代理会话。每 15 秒采样，DNS/签名采样在后台执行，不阻塞 helper 的状态控制队列；旧代次完成结果不能应用到新会话。网络改变时收紧旧接口例外，重新核验新原网卡 DNS、控制端点及网关；正在运行的核心换物理接口仍由完整接管串行重建。

临时解析超时且旧端点原路径仍核验有效时保留旧控制连接；失去接口或网关证据则撤销相关例外并保留公网阻断。helper 重启只保留路径重新核验成功的控制例外；原接口信息不明时收紧，再从 0600 的最小上下文恢复控制面维护。上下文只包含绕过项和 DNS 网络设置，不包含节点凭据、用户密码或运行时成功证明。

## 保护边界

这是目标级例外，不是进程级防火墙。其他程序和 Claude 也能访问被放行的目标端口。用户自己配置的宽 IP/CIDR 业务例外仍可能覆盖同地址控制端口限制，界面不应宣称只有云枢能直连。

厂商域名及已观察到的合法进程端点并非对所有云枢部署的完整依赖承诺。没有观察到的新服务/端口仍可能被拒绝，需要通过实机采样确认；不能因此放行整个 VPN 网段或所有公网连接。

本机 `lsof` 在部分指定进程没有匹配网络文件时会返回 1，即使有有效机器记录；仅该调用允许 0/1，并拒绝混入错误诊断的输出。其他网络命令仍默认仅接受退出码 0。

## 验证和安装

运行 `bash scripts/claude-bypass-checks.sh`。其中的 helper 测试使用隔离根目录、模拟 PF 和路由接口，覆盖控制准备、保留与撤销、失败、原 DNS 转发、后台控制队列响应、过期结果隔离和上下文恢复。

`.build/claude-bypass-helper-checks --inspect-local-yunshu` 仅只读核验当前云枢进程签名和端点数量，不更改代理或访问远程服务；普通用户执行时只能看到其权限范围内的套接字，不能冒充 root helper 全量证据。

交付为候选包，安装需同时更新应用和 helper 组件哈希。已有 0.16.16 会话不能用旧 helper 验收新能力。安装前先结束 Claude 使用，并明确解除旧保护，避免在旧版阻断下迁移时失去网络；解除期间允许直连。用户完成系统授权后再进行真实连接验证。

必须在公司外网络依次验收：云枢登录→启用保护→云枢保持或自动恢复→堡垒机登录与会话；再验收暂停/重连、网络切换、节点不可达、核心/GUI/helper 故障及 IPv4/IPv6/DNS/UDP。隔离检查和候选构建不能代替这些验收。系统重启空窗、企业特权组件改写 PF 和未知网关协议仍不作保证。


## 0.16.17 实机发现及 0.16.18 恢复修正

0.16.17 更新 helper 后实机启用失败：创建 TUN 后，PF 自有锚点规则读回为空；诊断确认 PF 已启用、自有根引用完整，但预期 1029 行的锚点实际为空。未查明清空来源，不能直接归因为云枢。该版本未通过实机验收。

0.16.18 的写操作在完整自有根引用、非空历史规则证据及无外部子锚点的条件下，可重载本应用空锚点；加载后短暂为空时只有限重试。非空外部改写或根引用变化仍拒绝覆盖。只读状态核验始终不写 PF。恢复流程的核心停止放入前置失败也会执行的清理路径，避免核验失败挡住停止。

隔离检查覆盖了空锚点、一次加载被清空、未知子锚点和非空外部规则等情形。该修正不证明能与持续清空 PF 的外部组件安全共存；若实机仍失败，保持未验收状态，不能继续声称保护有效。


## 0.16.18 安装回滚及常驻恢复入口

0.16.18 的维护恢复已停止残留核心并清理恢复记录，但安装后 helper 在 PF 恢复失败时退出，安装器等待不到控制套接字而回滚。当前不能把应用版本号更新视为 helper 安装成功。

0.16.19 将常驻启动的 PF、接管和控制面上下文恢复均改为捕获失败、记录明确原因，并继续建立现有鉴权的维护套接字。只读状态仍返回保护未核验，不降级成成功；不因此自动覆盖外部 PF、解除保护或放宽客户端鉴权。离线夹具覆盖了恢复异常仍可返回带能力信息的失败状态。


当前 PF 摘要进一步确认：原企业根规则保留，汐航锚点及根引用已不存在；macOS pfctl 查询缺失锚点可能退出码为 0 且输出 `DIOCGETRULES: Invalid argument`。新规则读取路径只在该唯一诊断文字与逐级锚点清单均证明缺失时返回空集，其他诊断一律失败。写恢复允许在根规则精确等于持久化的原始企业根规则时重建自有引用，并先建立引用再加载规则；不是忽略所有外部修改。
