# Claude 本机应用级保护：首阶段实现记录

状态：原型和离线检查；不满足发布条件。未安装系统扩展，未替换 `/Applications/汐航.app`，未修改当前代理、DNS、路由或 PF。本文不把源码完成、模拟检查通过与实机保护生效混为一谈。

## 已实现

- `ClaudeApplicationPolicy`：按经过身份解析的角色裁决，受保护程序只允许访问精确回环地址上的专用 TCP 代理端口；代理只能访问固定 IP、端口和传输协议。关闭访问后仍拒绝两者联网。其他已识别应用不受该策略限制，身份无法核验则拒绝。
- `ClaudeFilterPrototype`：独立的 `NEFilterDataProvider` 编译目标，使用 audit token 和 Security 框架核验动态代码身份及签名要求，同时核对来源应用和实际联网进程。显式添加 IPv4/IPv6 回环过滤规则，避免其他本地代理成为默认例外。
- 原型显式要求 `vendorConfiguration.prototypeOnly = true` 及 JSON 编码的 `policy: Data`。没有配置、版本不匹配或身份规则无效时启动失败。生产打包脚本不嵌入此目标，也没有自动激活入口。
- `ClaudeSafetyStateMachine`：串行操作状态、操作 ID 与策略版本核对、过期/未来/乱序证据拒绝、关闭期间旧监测结果隔离。只有过滤、应用/子进程覆盖、崩溃阻断、已有连接、DNS 和 IPv6 均确认，才允许派生可使用状态。代理失效且屏障有新证据时才标记已阻断。
- `ClaudeSafetyOperationStore`：独立的操作记录接口，以 0600 原子持久写入；保存原始恢复快照、固定出口、版本、操作 ID 和脱敏失败原因，不持久保存实时成功证据。重启后一律重新核验。
- `ClaudeNetworkFilterClient`：只读签名及嵌入组件检查。分别报告 Developer ID、签名团队、配置描述文件、过滤权限、主应用安装权限；文件存在不等于系统已授权或已激活。
- 新开启入口在任何 helper 请求、恢复记录写入或连接变更前检查发布门槛。当前原型始终拒绝正式开启，不提供环境变量绕过。已有旧 PF 会话保留恢复路径，状态改为“旧版整机保护已核验 · 应用级保护未确认”。

新增恢复记录尚未接入生产操作流程：它是后续扩展生命周期集成的持久化接口，不会自动读取或迁移旧 `claude-safety.json`。因此不会借此改变正在运行的旧版会话。

## 尚未实现或验证

这些是发布阻碍，不能仅靠补签名宣告完成：

1. 正式 Developer ID 证书、主应用/扩展 provisioning profile、对应 entitlement、公证及系统授权；当前机器没有可用代码签名身份，安装应用为 ad-hoc。
2. 系统扩展激活/更新与 `NEFilterManager` 配置生命周期、独立专用代理入口和 IPC 状态证据。还需核对监听进程身份、防止代理退出后端口被其他程序替占；端口可连接不能代表专用代理可信。当前代码不调用这些修改系统配置的 API。
3. Claude Code 任意子进程、MCP 和系统代理代发连接的可靠归属。原型只识别签名规则直接匹配的进程；未匹配的已签名子进程可能归为其他应用，因此绝不能发布。专用浏览器和各入口也未自动登记。
4. 系统代解析 DNS、已有连接的重新裁决、扩展退出及开机空窗的持续阻断。原型的 `stopFilter` 不会、也不能在用户态回调中证明系统已保持阻断。
5. 关闭/退出后仍保持 Claude 阻断的实际系统策略。新状态机只建模该前置证据；旧 PF 关闭/退出路径仍恢复原网络，不能把它当作新模式。
6. 云枢实际隧道与公司业务连通性。原型没有运行，也没有修改公司规则。旧版 helper 的云枢静态 IP 兼容逻辑仍保留，须在应用级方案通过验收后随旧 PF 模式迁移撤除，不能现在移除而使旧会话断网。

未知身份的拒绝可能影响其他系统服务，子进程放过则可能泄漏；两者都需要在正式沙盒和系统授权环境下验证，不能在当前用户网络直接启用试错。若平台能力无法满足持续阻断要求，停止发布并重新评估架构，而不是依靠轮询后杀进程弥补窗口。

## 可重复验证

在仓库根目录运行：

```bash
bash scripts/claude-filter-checks.sh
bash scripts/claude-safety-checks.sh
```

第一个命令只编译、运行离线策略/恢复测试、生成覆盖率并读取已安装应用的签名状态。原型 `--preflight` 固定返回退出码 2，表示正式发布未通过；脚本校验这个拒绝行为，不将它标成部署成功。

第二个命令使用独立配置和模拟 helper，含真实生产预检拒绝场景；其他旧版回归夹具显式替换预检以验证原先恢复流程，不构成系统扩展证据。检查中不触碰用户日常凭据、不安装 helper、不写入网络配置。

日志及覆盖报告在 `.build/claude-filter-checks/`。Swift 工具链的分支列若显示 0 / `-`，代表没有取得可验收的分支覆盖证据，不代表所有分支通过。过滤 provider 本身和实际签名成功分支尚无覆盖；定向变异检查不能代替全项目或正式发布门槛。

只有上述阻碍全部消除，并通过 VPS/核心/GUI/扩展退出、重启、休眠、网络切换、IPv4/IPv6/DNS/UDP/长连接抓包和云枢业务双向验收后，才允许接入正式按钮与替换应用。
