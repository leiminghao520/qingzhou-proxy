# 辅助服务升级恢复死锁修复

## 现场与原因

2026-10-23，0.13.4（58）客户端替换后，旧辅助服务仍绑定旧客户端代码身份；存在恢复记录时安装脚本拒绝覆盖，恢复与退出又依赖不可用的旧控制通道，导致三个入口互相阻塞。12:22 的恢复记录涉及外部 utun8 路由以及 239.255.255.250/32 组播项。

原生采样将组播父项和邻居缓存均规范为 link#11；删除满长父项后，残留缓存被保守判为歧义，继续阻塞恢复。先前夹具未覆盖同 link# 缓存保留这一组合。

## 修改

- 管理员安装入口先调用随包恢复器，备份恢复意图、旧固定组件和路由审计，再停止旧服务，以保留外部网络的方式清理本次轻舟残留；完成后才更新固定组件及客户端身份。
- 恢复失败保留记录，不启动旧版严格恢复循环；支持服务已停止时再次执行维护。
- 新服务身份拒绝通过结构化失败帧返回明确原因，不只静默关闭通道。
- 仅针对特定 SSDP 组播目标，在当前完整整表可证明同接口、同作用域、相同 link#、完整父网段和缓存标志及真实组播 MAC 时，将剩余邻居缓存判定为外部系统缓存；不删除该缓存。缺失证据、独立静态项或其他出口竞争仍拒绝自动处理。
- 安装后恢复显式保留外部代理。
