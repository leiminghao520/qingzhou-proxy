# 0.12.4 protection 阶段 EINVAL：修复与离线证据

## 定位结论

现场为 2026-10-22 23:26。审计事务 `4E01BC58-BA03-4211-BD8A-A6E57AC7C891` 的第 680 次操作，本地写入编码失败。通过事务盐与参数摘要匹配，唯一对应 `fe80:0:0:1::/64`，网关 `fd71:717a:259::1`。保留了脱敏审计及匹配结果。

原规划把原接口的 `fe80::/64` 当作普通全局排除做 CIDR 差集，产生链路本地碎片，再试图作为无作用域全局路由写入。现有严格编码器拒绝这种组合，返回 22。现场 raw EINVAL 来自提交前编码错误；并非这一次已经发生了 kernel panic，也不能据此证明以前 panic 的完整触发链已消除。

只读快照与现有配置的离线重建同样生成了该前缀和一批相同类型碎片。修复前编码失败列表、审计哈希匹配与修复后列表均保留，不依赖真实内核试写。

## 源码修复

- 原接口链路本地、组播路径继续按已确认的精确前缀和接口作用域保留，验证它们比相关全局捕获更具体；不把某个接口的 `/64` 扩成整个 `fe80::/10`。邻近未确认地址也不被自动标为物理绕过。
- 保留 CIDR 差集、企业保护、原生后端与 4096 预算。显式绕过组合若仍产生无法表达的全局链路本地/本地组播前缀，在纯规划阶段拒绝，不跳过该项继续执行。
- 启动路径在 TUN 接口存在后、任何路由写入前，对全部待新增保护、物理作用域和捕获路由编码并执行现有独立结构校验。动态更新也在新增前预检整批。预检不调用路由交换。
- 编码构建由实际提交与预检共用；原 C 编码器、独立验证器与 socket 提交条件均未放宽。UI 新增“整批校验路由报文”阶段。

这是依赖原接口作用域与最长前缀优先级的捕获模型修正，真实 macOS 上的作用域流量结果仍需单独验收，不能由内存模型替代。
