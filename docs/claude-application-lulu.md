# Claude 专用代理与 LuLu（0.16.22 候选）

日期：2026-11-17。应用级方案保留其他应用原有网络，不启用整机 PF 或 TUN。汐航负责专用代理，LuLu 负责出站规则，两者独立；汐航不根据 LuLu 安装状态显示“保护已生效”。

## 代理

首页 Claude 区域或菜单栏选择固定节点并启动“Claude 专用代理”。入口为 `http://127.0.0.1:17891`，核心为随包 `QingzhouClaudeCore`，签名标识 `cn.qingzhou.proxy.claude-core`。仅允许固定公网 IP、单端口 TLS 节点；不接受 Shadowsocks、域名节点、跳跃端口和明文 VLESS。

配置只有一个出口和通过该出口访问的 HTTPS DNS，无 DIRECT、备用组、自动选择、控制端口、本地 DNS 或局域网直连规则。不改变系统代理、DNS、默认路由和 PF。停止专用代理、恢复网络或正常退出会停止该核心，但不修改 LuLu 持久规则。重新启动需手动选择节点，避免开机在规则尚未确认时自动连接。

旧版整机 PF 保护保留为明确标注的独立功能，不能与专用代理同时开启。应用级方案不要求更新原管理员 helper，也不使用它的网络接管能力。

## LuLu 规则

关闭“允许 localhost 流量”和“允许 DNS 流量”通用绕过，不开启允许列表、全局阻断或被动模式。其他应用的已有规则保留。

| 程序身份 | 允许 | 拒绝 |
| --- | --- | --- |
| Claude Code 原生程序 | 127.0.0.1:17891 | 其余目标与端口 |
| Claude Desktop | 127.0.0.1:17891 | 其余目标与端口 |
| Claude Desktop Helper | 127.0.0.1:17891 | 其余目标与端口 |
| QingzhouClaudeCore | 本次固定 VPS IP:端口 | 其余目标与端口 |

最后一条必须与当前专用节点对应；更换节点前先停止专用代理并更新精确规则，不能放行任意服务器。LuLu 地址及端口规则不能冒充协议级过滤证明。核心生成配置限制实际使用的传输方式。

## Claude Code

使用随包脚本启动：

```bash
'/Applications/汐航.app/Contents/Resources/claude-safe.sh'
```

此入口统一大小写 HTTP(S)/ALL_PROXY 并清空 NO_PROXY，只允许进程及普通继承子进程通过 localhost:17891 发起 TCP 连接。代理不运行时拒绝启动。`sandbox-exec` 为 macOS 已弃用接口，本机兼容检查通过并不代表未来 macOS 保证支持；实际启动失败时不降级为普通 claude。

LuLu 的 Claude 本体规则也约束直接从终端启动的原生 claude；但其普通子进程不自动继承同一 LuLu 程序规则。需要子进程网络限制时必须使用上述入口；不封禁整个 Terminal、node、curl 或 Python。

## Desktop 与网页

Desktop 需以专用代理启动并重新建立连接，不能把环境变量支持等同于所有 Electron 连接都已使用代理。主程序和 Helper 的 LuLu 拒绝规则作为后备；若某个组件不遵守代理设置，应请求失败而不能直接放行。

当前不覆盖日常浏览器里的 Claude 网页。浏览器同时访问其他网站时，以进程全局封禁会影响其他网站；需要独立浏览器实例或单独的网页隔离设计。

## 仍需实机核验的边界

- LuLu 规则存在不代表所有当前连接、未来 Helper 或代码更新都已被正确识别，必须重启客户端并观察阻断日志。
- Claude Code 调用沙箱外常驻 MCP、Docker daemon、浏览器或系统代理服务的间接联网不在普通子进程 TCP 沙箱的完整保证内。
- 回环端口被其他进程替占、过滤器被停用或退出、系统重启空窗与特权程序改写均不能由本次隔离检查证明安全。
- 不显示“绝不泄漏”或“应用级保护已通过验收”。用户负责恢复网络实机验收；本轮不会主动制造整机网络故障。
