# macOS 睡眠唤醒断开修复

日期：2026-10-17，修复版本 0.8.11（25）。

## 现场证据与定位范围

本机系统电源记录显示 13:46:23 从睡眠唤醒。应用 diagnostic.log 在 13:46:26 记录网络重新激活失败：恢复路由 `239.255.255.250/32` 时提示“网络操作超过总截止时间”，随后停止核心并保留恢复记录。13:46:58 应急恢复成功，13:47:14 重新连接后的检测通过。应用主进程从前一晚持续运行，这次是连接停止而非主应用崩溃。

`NetworkInspection.command` 原先用 `Date` 设置并核对默认十秒截止时间，却用 `DispatchQueue.asyncAfter` 的 uptime 时钟终止子进程。前者计入系统睡眠及日期调整，后者在 Apple 平台不计睡眠。因此跨睡眠的命令即使成功返回，也可能在最后的日期检查中被误判超时。路由恢复会将该错误作为未完成恢复处理，终止本次重规划，要求手动恢复。

该计时缺陷可由源码与模拟测试复现，与现场时间顺序吻合；现有日志没有记录旧命令的启动时间与实际退出状态，不能据此证明它是所有睡眠断开的唯一原因。

## 修复

普通系统命令的默认十秒预算统一使用 `DispatchTime.now().uptimeNanoseconds`，使成功判定和终止计时器采用相同时间基准。睡眠和系统日期调整不再消耗默认命令预算。调用方明确传入的截止时间保留原有语义，避免放宽 DNS 请求总预算。错误消息增加命令名称及预算类型，方便后续区分真实超时。

不增加忽略所有权冲突或无条件自动连接的行为；已有网络变化重规划流程在命令正常完成时继续工作。

Apple 时钟说明：https://developer.apple.com/documentation/dispatch/dispatchtime/init(uptimenanoseconds:)

## 生效要求

修复位于管理员辅助服务所链接的共享命令执行代码中，必须同时更新应用与系统辅助服务，版本均为 0.8.11。只打开新 app、保留旧辅助服务不能让本次修复生效。安装前应安全断开、完成旧连接恢复，再由 macOS 管理员授权窗口安装新服务。
