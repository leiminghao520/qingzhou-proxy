# 恢复普通网络（0.16.21 / 104 候选）

2026-11-17。本次优先修复汐航出问题后的恢复入口。尚未通过实机故障注入和公网、云枢业务验收；不把隔离检查等同于整机恢复保证。安装候选包与启用管理员服务是独立步骤。

## 使用行为

- 首页、工具栏、菜单栏及设置中的“恢复网络”统一表示：停止汐航代理、解除汐航断网保护、恢复本次接管前的网络设置并关闭自动连接。Claude 随后允许直连。
- 普通断开、暂停 Claude 代理和正常退出仍保留 Claude 保护；它们不替代“恢复网络”。
- 恢复前取消自动重连、唤醒恢复和保护轮询。配置或 Claude 保护记录损坏不再禁用恢复入口。
- 若管理员服务不支持独立恢复、失联或恢复报错，自动使用随包恢复器。macOS 可能要求管理员授权，密码由系统接收。
- 独立恢复先停用旧服务，等待服务和原进程退出，再执行新恢复器。成功或失败后均不重新启动旧服务，避免刚恢复又重新阻断。
- 独立恢复后如需再次连接，请安装或更新辅助服务；不自动恢复代理连接。

## 恢复事务

`maintenanceStatus` 仅提供维护能力和事务状态，不以保护核验成功作为恢复前提。`restoreNormalNetwork` 先持久保存恢复意图，再撤销后台更新来源并改变代次，分别尝试接管清理和 PF 解除。接管失败仍尝试释放独立的自有屏障；部分完成时保留事务并明确报错，不显示整体成功。

网络清理通过后，应用正式提交恢复配置并关闭自动连接，再确认事务。配置提交、确认或管理员授权失败时保留待处理状态，可重复点击恢复网络。辅助服务重启发现恢复意图时继续恢复，不重新施加保护。确认操作可安全重试。

损坏的 Claude 保护记录或正常网络恢复意图先保留私有归档，再继续明确的恢复操作。损坏的路由/DNS 接管记录无法凭空重建原设置：保留记录并报错，独立的自有 PF 阻断仍尝试解除。

只清理有所有权证据的汐航路由、DNS、代理及 PF 规则。保留后来被企业 VPN 或其他软件接管的设置；不执行全局清空 PF、全局连接状态清理或关闭 PF。未知规则冲突、外部网络故障及上游不可达不能宣称已恢复联网。

旧 PF token 缺失、失效或引用不可读不再阻止自有过滤规则的解除；保留审计及告警，不释放所有权不明的启用引用。

## 应用无法操作时

使用**本候选包中的**恢复器，不要从旧应用复制同名脚本。先退出汐航，再在终端执行（将路径替换为本候选应用的实际路径）：

```bash
sudo /bin/bash '/本候选应用路径/汐航.app/Contents/Resources/recover-helper.sh' '/本候选应用路径/汐航.app'
```

此命令解除汐航保护并保持旧服务停用。备份位于 `/Library/PrivilegedHelperTools/qingzhou-recovery.*`。外部终端恢复后，应用中的恢复入口可继续完成用户配置及事务确认。

`--for-update` 是安装器内部的升级恢复模式，保留保护；用户要恢复普通网络时不要加此参数。`--acknowledge` 仅在应用已正式提交恢复配置后使用，不是跳过清理的开关。

## 验证

- 应用模型隔离回归：正常恢复、保护中恢复、服务失联转独立恢复、确认失败重试、配置加载失败、保护记录损坏，以及原有安全模式场景。
- 辅助服务隔离回归：保护异常仍可维护、接管记录损坏仍尝试解除 PF、失败禁止确认、重启不重施保护、恢复意图损坏归档及幂等确认。
- 管理员脚本隔离回归：旧服务不停退出、未知服务状态、服务已卸载、恢复失败、离线确认、升级保留保护及原有安装回滚。
- 防火墙及退出恢复的现有定向回归。

这些检查不修改系统网络。实机待验证：更新后的管理员服务、TUN/核心/GUI/helper 异常、休眠和网络切换后恢复，并持续核验公网与云枢实际业务至少十分钟。恢复设置不等于证明上游网络可用。
