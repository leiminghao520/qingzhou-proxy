首页连接区域和菜单栏提供同一个“Claude 安全模式”开关。开启时保存原网络设置及连接状态，切换固定 IP 节点、完整接管、全部代理、严格代理 DNS 和断线保护；关闭时恢复原设置。不能确定节点时只需首次选择，之后记住该节点。

## 保护边界

- 保护覆盖整机公网流量，因此 Claude 网页、桌面端和 Claude Code 都受同一出口限制。
- 仅放行固定 VPS、局域网及链路基础流量。公司公网路由不作为额外公网出口，这类目标在模式开启时也可能无法访问。
- 手动断开、正常退出汐航或执行应急恢复会解除保护，之后仍运行的 Claude 可以直连。开机尚未启用保护时不提供保障。
- 初次建立保护会清理已有连接状态。防火墙环境不兼容或辅助服务不支持严格出口限制时拒绝开启。

### 0.16.13 深信服防火墙兼容修复

对只包含已识别深信服锚点引用的运行时根规则，持久保存原引用及顺序，在其前面加入独立的汐航拒绝锚点。只通过 `pfctl -R` 更新过滤引用，不改 `/etc/pf.conf`、NAT 或深信服子锚点内容；关闭时只在根规则仍与本次记录一致时恢复原引用。未知结构或并发外部规则改动仍拒绝覆盖。规则中的 `quick` 保证拒绝匹配后停止后续规则处理，参见 [PF 锚点说明](https://www.openbsd.org/faq/pf/anchors.html)，具体命令行为同时按本机 macOS 的 `pf.conf(5)`、`pfctl(8)` 核对。

只读防火墙预检或状态核验返回失败，不再关闭持有代理会话的控制通道；传输损坏、取消及写操作失败仍关闭通道。

## 状态和恢复

显示“保护已生效”需要辅助服务核验实际防火墙规则，而且放行清单必须与当前固定节点的严格清单完全一致。磁盘恢复记录、开关位置和辅助服务版本号不能单独证明保护生效。辅助服务不可读时显示保护未确认，不沿用旧的成功状态。

连接失败后保留已经建立的保护，不经过普通配置事务自动恢复旧出口。可以点击普通连接按钮重试，或关闭安全模式还原原网络。安全模式期间配置变更被拒绝，避免其他入口更换出口或降低保护。

恢复点保存在应用数据目录的 `claude-safety.json`，以 0600 权限原子持久写入，记录原网络设置、原连接状态、配置标识和安全节点引用，不包含节点密码。先写恢复点再停止原连接；先确认解除保护并保存原设置，再清除恢复点。异常退出后可通过同一个开关恢复。记录损坏时保留原文件并拒绝普通连接和配置覆盖。

## 验证方法与限制

`bash scripts/claude-safety-checks.sh` 使用独立配置、内存凭据和模拟辅助服务，覆盖开启关闭、节点记忆、重复点击、预检失败、连接失败、解除失败、辅助服务不可读、规则证明不匹配、配置限制、跨进程恢复和损坏记录。该检查不安装辅助服务、不连接 VPS、不改写系统网络。

`QingzhouChecks disconnect-protection-checks` 检查 IPv4/IPv6 拒绝规则、已有连接状态清理命令、恢复记录、规则篡改及严格放行清单证明，管理员操作使用夹具，不能代替真实断网验收。

2026-11-16 隔离结果：安全模式 60 项检查通过，防火墙 95 项断言通过；将 `QingzhouChecks`、`qzhttp` 和 `sing-box` 放入完整隔离检查包后，全量回归 158 个场景、20,121 项断言通过。直接运行未附带 `qzhttp` 的 SwiftPM 检查程序时，退出恢复检查曾因缺少兼容组件失败，不能将该次执行计为通过。

当前交付为候选构建。真实网络下的 VPS 不可达、核心/GUI 崩溃、睡眠唤醒、IPv4/IPv6/DNS 抓包以及新版辅助服务安装尚需实机验收；不能依据隔离检查宣告没有网络泄漏。全项目 100% 行/分支覆盖及至少 80% 变异检出率门禁尚未取得，本次也未宣告通过。

2026-11-16 的 0.16.13 更新已补充本机实测：应用与辅助服务安装通过，安全模式开启成功；两条绑定物理网卡、固定公网 IP 的 HTTPS 直连超时，经本地代理的 Apple HTTPS 返回 200。主动结束当前应用所属的用户态代理入口 `qzhttp` 后，连续 10 次物理直连均未成功，界面显示公网阻断；自动恢复因所有权冲突转为手动处理，点击连接后恢复。关闭安全模式后同一物理直连返回 200，再次开启成功并保持开启。`/etc/pf.conf` 哈希前后不变。隔离控制通道 28 项、防火墙 113 项、安全模式 60 项通过；全量 158 场景、20,121 断言通过。
