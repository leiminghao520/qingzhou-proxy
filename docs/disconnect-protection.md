# 可选断线保护（0.16.11 候选）

## 行为

设置 → 网络接管与管理员辅助服务新增“断线保护（可选）”，默认关闭，旧配置不自动开启。开关先进入草稿，点击应用才保存；保存成功不等于防火墙已经生效，连接时成功加载独立拒绝规则后才开始保护。

开启要求手动选择服务器地址为固定公网 IP 的单个节点，自动使用完整接管、全部代理和严格代理 HTTPS DNS，关闭 HTTP 兼容模式。不接受域名节点、本地 SSH 转发节点、自动选择或策略组。当前配置中的 `clash · TCP 备用` 使用固定 IP，符合节点地址条件；Hysteria2 的域名节点暂不符合。节点类型不是限制原因，Hysteria2 改为固定服务器 IP 并正确保留 SNI 后同样可用。

运行配置只包含所选节点，选择器不包含自动、其他节点或 DIRECT；原订阅节点、规则仍保存在用户配置中。保护配置生效期间不能直接切换节点，需先关闭保护。普通规则在保护期间不参与公网分流。

独立防火墙记录为辅助服务目录下 `disconnect-protection.json`，权限 0600，不随路由恢复日志删除。连接中允许本次 TUN；核心、控制通道或 GUI 异常退出、自动恢复时先收紧为无 TUN 的拒绝规则，再恢复路由。辅助服务重新启动时读取记录并收紧规则。首次加载会清理 IPv4/IPv6 旧连接状态，因此已有连接可能中断。重连不得更换固定出口或例外集合，环境变化不能核实时保持阻断并交给用户处理。

手动断开、正常退出、关闭选项或应急恢复会在原接管停止后显式解除保护。自动失败清理不能解除。退出独立核验仍要求保护已解除，不能把残留阻断报告为网络已完全恢复。管理员恢复脚本的显式恢复入口也解除保护。

## 公司网络与限制

只在过滤根规则为可验证的独立 Apple 锚点、且该锚点没有其他组件时启用。仅加载自己的随机子锚点，不重载根规则，不改 `/etc/pf.conf`，不覆盖深信服规则。存在企业防火墙或其他无法确认的组件时拒绝开启。规则被外部改写时保留记录并停止自动处理，不认领或清空其他组件。

局域网、链路基础流量、固定节点 IP 和本次快照确认的公司路由作为例外。它不是无例外断绝一切网络，也不承诺阻止所有 DNS 元数据离开本机。公网 DNS 不因节点引导被额外加入直连例外。IPv4 和 IPv6 都生成拒绝规则。固定节点不等于可证明 VPS 上游 NAT 或云商公网 IP 永久不变。

本机 `/etc/pf.conf` 含深信服锚点；当前实际加载的根规则尚未通过管理员权限核实，不能把配置文件内容等同于实际生效规则。当前候选未安装，未启用，也未对真实核心做断线、崩溃、休眠或重启验收。不能据此宣称全机断线保护已经可用。网络出口保护不能保证第三方账号不被封禁。

## 复现

```sh
scripts/swift-local.sh run QingzhouChecks disconnect-protection-checks
bash scripts/disconnect-protection-ui-checks.sh
python3 scripts/disconnect-protection-mutations.py
bash scripts/connection-recovery-ui-checks.sh
bash scripts/quit-release-checks.sh
bash scripts/build-app.sh /绝对路径/候选包输出目录
```

所有新检查使用临时目录和内存命令夹具。变异脚本只在 `.build/disconnect-protection-mutations` 修改副本，并恢复覆盖率对应的基线副本；不修改正式源码。
